# 3D 场景性能监测与动态分辨率

适用场景：太阳系总览、地球、月球、火星、PlanetScene 各天体、土卫六着陆视图。

## 正常使用

默认启用动态分辨率，不增加页面控件。起始像素比仍为设备像素比（最高 2），下限 1。仅改变绘图缓冲区尺寸，不改变模型、标签、镜头和页面布局。

启动后至少观察 3 秒。连续两个约 1 秒窗口平均帧耗时超过 22.22ms（低于约 45 FPS）时，像素比乘 0.85；每次调整后冷却 3 秒。连续 6 个平稳窗口（均值低于 17.5ms、95 分位低于 21ms）后提高 0.1，最多恢复到初始值。

后台/前台切换会丢弃当前采样和连续判定，避免后台限帧触发降画质。设备像素比为 1 时保持 1，不继续模糊画面。低分辨率无法解决所有主线程计算瓶颈。

## 查看记录

在 URL 的 # 前加入 `?perf=1`，例如 `http://localhost:5173/aurora/?perf=1#solar-system`。

浏览器开发者工具的 Console 中执行：

```js
window.__auroraPerformance()
```

返回 active（当前场景）和 completed（最近结束的场景，最多 12 个）。每个场景保留最近 60 个采样窗口：

- fps、frameMeanMs、frameP95Ms：帧节奏、平均帧间隔、95 分位帧间隔。
- workMeanMs：动画回调内 JS 与渲染提交的平均耗时；不是 GPU 执行时间。
- slowFrames：窗口内超过 33.33ms 的帧数。
- longTasks、longTaskMs：浏览器 Long Task API 记录的页面主线程长任务；不是该场景独占耗时。多个活动场景可能看到相同页面长任务。
- pixelRatio：该窗口使用的像素比。调整发生在窗口结尾，下一窗口体现新值。
- drawCalls、triangles、geometries、textures：窗口结束时最后一次绘制/资源统计。
- activity：窗口内检测到画布按下、拖动或滚轮操作时为 interaction，否则 idle；不代表没有程序触发的动画。
- firstAnimationFrameMs：建立监测器到首次动画回调开始的时间，不等于完整首屏显示时间。

不支持 Long Task API 的浏览器，longTasksSupported 为 false。记录只留在当前浏览器内存，不上传、不保存跨刷新数据。

对照固定分辨率时，使用 `?perf=1&adaptiveDpr=0`；刷新后生效。这样仍可收集指标，但不自动调整。

## 验证边界

策略测试覆盖孤立卡顿、持续掉帧、恢复冷却、像素比边界和后台切换。监测器测试覆盖实际调用渲染器调整、记录与事件清理。浏览器检查覆盖场景显示和切换。

这些检查证明机制接入与行为，不代表所有设备都能达到 60 FPS，也不能把不同场景、冷/热缓存、不同设备的读数直接当作优化前后对照。

## 场景、轨道、标签与纹理优化

- 总览通过 KeepAlive 保留一个实例。离开时停止动画采样和键盘监听，返回时恢复并播放原有返回镜头。诊断里的 id 应保持不变，paused 表示保留但暂停；completed 只包含真正释放的场景。保留一个 WebGL 场景会增加驻留显存，独立天体页仍按原方式释放，不缓存所有页面。
- 地球卫星位置与密集轨道线采样在 Worker 中执行，传输 TypedArray 缓冲区。每秒计算当前与下一秒的位置，主线程逐帧插值；元素变化使用 generation 丢弃旧数据，后台暂停，卸载终止。失效/过期的位置不继续显示为实时位置；Worker 不可用时回到原有计算方式。
- 标签更新复用内容未变的数组/对象，忽略不足 0.05 像素的投影噪声；太阳系标签与镜头逐帧同步，不单独限频，避免缩放和镜头移动时出现阶梯式跳动。标注改用 transform 移动，保持原有短线、聚合和左右布局。
- 本地新增 2048 宽的预览纹理（由既有图片缩小生成）。总览和预热加载预览；地球、月球、火星及通用行星的独立页面，球面预计覆盖超过 1800 个绘图像素时请求原始高清贴图，回到 1400 以下恢复预览。加载高清时保留现有画面，卸载后的异步回调不再修改场景。高清文件仍在项目中。
- 纹理缓存会保留已加载的高清对象；该策略减少初始加载/上传，不能保证拉近后已占用的所有显存立即释放。
- details 可查看地球 orbit.worker、轨道快照时间与数量，以及独立天体 surfaceTextureWidth。判断是否真的读取了图片时，要排除开发模式下 URL 以 ?import 结尾的轻量资源模块。
